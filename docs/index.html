Why the all-time rate looks so high — and what to trust instead

Short answer: exclude untagged bugs and measure recent months separately. Excluding untagged bugs alone isn't enough — the old backlog is so sparsely tagged that what's left over is still a small, skewed sample.

What's actually happening "Issued by" tagging discipline has changed sharply over time. In July, only 57 of 158 bugs (36%) had the field set at all — too little and too skewed toward Support (who gets auto-tagged via the support intake process) to trust. By August that jumped to 82% tagged. Since September 1, it's 100% — every single new bug has Issued by set. The all-time 74.3% figure blends all of that together, so it mostly reflects old data-entry gaps, not current quality.

Note on the HW project Shelly's Jira also has a separate HW — "Hardware Team" project. It does not track defects the way FW/FE do: of its 263 items, 217 are "Task" and 2 are "Story" — zero use the "Bug" issue type, and the "Issued by" field (the backbone of every escape-rate number on this page) has never been set on any of them. What each metric measures

Issued by

Required select field on every FW/FE Bug. Support = a customer hit it (escaped to prod). QA / QA Automation / PO / Development / Integrations / Front End / Back End / Documentation = caught internally before release. This is the backbone of every "escape rate" number on this dashboard.

Firmware Version

customfield_13320. As of this rebuild it's a clean multiselect of predefined version strings (no more free text). An issue can carry more than one version if it was verified as reproducing across a regression window — that issue is then counted once per version it's tagged with.

Shelly Component

customfield_13319. Subsystem/protocol tag (Zigbee, MQTT, Matter, HTTP, Schedule, etc). Used for the Component filters on the Version Explorer and Devices tabs. Distinct from the "Feature" field, which is not currently surfaced here.
Field migration note The Firmware Version field used to be free text (customfield_13220) with inconsistent formats and unreliable JQL text search — a version like "2.0.1" would sometimes return 0 results despite being visibly present on issues. That field has been superseded by a clean predefined-values field (customfield_13320), which this entire dashboard is now built on. The old field is no longer used here; its historical data isn't included since it can't be reliably reconciled with the new one.
Coverage 28 of 522 FW bugs currently carry a Firmware Version tag — this field is still being adopted retroactively, so version-scoped numbers above cover a growing subset, not the full backlog. All portfolio-level totals (headline KPIs, Issued-by pies, escape rate) use the full 522/696 bug counts regardless of version tagging.
